Files and projects

Open a file or a project

Choose File › Open… (⌘O) and select a file or a folder. A folder opens as a project: a window with the file tree on the left. You can also drag files to the Dock icon or use Open With in the Finder. Recent files and projects are in File › Open Recent.

When MinorIDE starts with nothing to open, the welcome window lists recent projects and files: double-click one or select it and press Return. Show it any time with Window › Welcome to MinorIDE (⇧⌘1).

Tabs

Files of a project open as tabs of one window. Switch tabs with ⌃Tab and ⌃⇧Tab. File › Reopen Closed Tab (⇧⌘T) brings back the last closed file. A dot in a tab’s close button means the window has unsaved changes.

The file tree

Click a file to open it, or select it and press Return. Hold Option (⌥-click or ⌥Return) to open the file in the other part of a split editor. Control-click a file or folder for New File…, New Folder…, Rename…, Move to Trash, Show in Finder and copying its path.

Show or hide the tree with View › Show Sidebar (⌃⌘S), the right panel with ⌃⌘I and the bottom panel with ⌃`.

Files changed on disk

When a file changes outside MinorIDE (for example after git checkout) and you have no unsaved changes, it reloads quietly and keeps your cursor. If you have unsaved changes, a bar offers Reload, Keep Mine or Compare. A deleted file stays open; saving creates it again.

Restricted Mode

A project you open for the first time is in Restricted Mode, shown by a bar above the editor. Git, language servers, tools such as PHPStan, run configurations and the debugger can run code from a project’s files and settings, so MinorIDE doesn’t start them for the project, and it doesn’t read .minoride/local.json. Editing, colouring and search work as usual.

If you trust the project’s authors, choose Trust Project… in the bar or in the File menu. MinorIDE remembers the choice for the folder outside the project, so a downloaded repository cannot trust itself. File › Restrict Project takes the trust back.

Windows after quitting

MinorIDE follows Close windows when quitting an application in System Settings › Desktop & Dock. When it is off, the projects and files you had open come back the next time you open MinorIDE (untitled windows don’t). Hold Option in the MinorIDE menu for Quit and Keep Windows or Quit and Close All Windows to do the opposite once.

Saving automatically

Turn on Save files automatically in MinorIDE › Settings… (⌘,), tab General. Edited files are then saved when you switch to another tab, window or app. A file that changed on disk meanwhile is not saved automatically, so you don’t overwrite someone else’s changes; untitled files are not saved either.

After a crash

While you edit, MinorIDE backs up unsaved text every few seconds. If it quits unexpectedly, the next launch puts the text back into the editors, still unsaved, and tells you how many files were recovered. The backups are stored in your Library folder, readable only by you, and are removed when you save or close without saving.

Local History

Each time you save a file, MinorIDE keeps a copy of it for 14 days (the first save also keeps the version that was on disk before). Choose File › Local History… to see the versions, each compared with the text in the editor. Restore This Version puts it into the editor; you can undo it with ⌘Z, and it is saved only when you save the file. The copies are stored in your Library folder, readable only by you; files over 5 MB are not copied.

Binary and large files

Binary files are not opened as text; you can view their bytes with Show Hex or preview them in the Finder. Files over 5 MB or with very long lines open without syntax colouring to stay fast. Files over 256 MB open read-only: you can read, search and copy, but not change them (the status bar shows Read Only).
